以下はGFMで利用できる代表的な記法です。移植性が必要な文書では、表、タスクリスト、アラート、脚注、数式、Mermaidなどが公開先で利用できるかを先に確認してください。

## 基本の記法

| 目的             | 入力                            | 表示の要点                                    |
| ---------------- | ------------------------------- | --------------------------------------------- |
| 見出し           | `## 見出し`                     | `#`は1〜6個。前に空行を置きます。             |
| 強調             | `**重要**`                      | 強い強調には`**`を使います。                  |
| 打消し           | `~~廃止~~`                      | GFMの拡張です。                               |
| インラインコード | `` `npm run build` ``           | コマンド、識別子、ファイル名に使います。      |
| リンク           | `[表示名](https://example.com)` | URL単独ではなく、意味のある表示名を付けます。 |
| 画像             | `![説明文](./image.png)`        | 代替テキストを省略しません。                  |
| 引用             | `> 引用文`                      | 引用元を本文または直後に示します。            |
| 水平線           | `---`                           | 話題の大きな区切りだけに使います。            |

## リストとチェック項目

順序に意味がない項目は`-`、手順は`1.`を使います。番号付きリストはすべて`1.`で書いてもレンダラー側で連番になりますが、レビューしやすさを優先して実際の順番を書く運用も有効です。

```md
- 設計を確認する
- 実装する
- レビューを依頼する

1. リポジトリを取得する
2. 依存関係を導入する
3. テストを実行する

- [x] 既存仕様を確認
- [ ] 公開URLを確認
```

GitHubでは`- [ ]`と`- [x]`がクリック可能なタスクリストとして表示されます。Issue本文のタスクリストは進捗表示やIssue参照との連携を持ちますが、複数Issueを階層的に管理する用途ではsub-issuesを検討してください。[1]

## コードと表

コードブロックはバッククォート三つで囲み、言語名を指定します。言語指定は読みやすさとシンタックスハイライトの両方に役立ちます。

```ts
const greeting = (name: string) => `Hello, ${name}`;
```

表は比較に有効ですが、セルに長文や複雑な構造を入れないでください。狭い画面で読みにくくなる場合は、見出しと箇条書きに分けます。

```md
| コマンド        | 用途                   |
| --------------- | ---------------------- |
| `npm run lint`  | Markdownを検査する     |
| `npm run build` | 公開用サイトを生成する |
```

## 参照リンクと脚注

同じURLを複数回使う場合は、本文の可読性を保つため参照リンクを使います。

```md
Astroの[GitHub Pages公開手順][astro-pages]を確認します。

[astro-pages]: https://docs.astro.build/en/guides/deploy/github/
```

GFMでは脚注も使えます。短い補足には有効ですが、重要な前提や手順を脚注へ隠しすぎないでください。

```md
これは重要な判断です。[^reason]

[^reason]: 変更の背景をここに記載します。
```

## レビュー前チェック

- 文書の目的を表すH1見出しが一つあるか。
- 見出しレベルが`##`から`####`のように飛んでいないか。
- リンクの表示名だけで遷移先の意味が分かるか。
- コードブロックに言語名があるか。
- 画像に内容を説明する代替テキストがあるか。
- 表が狭い画面でも読める量に収まっているか。
