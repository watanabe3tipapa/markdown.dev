VS
CodeにはMarkdownの編集、プレビュー、見出し操作、ローカルパス補完、リンク検証、Mermaid、数式表示などが組み込まれています。[1]
拡張機能を増やす前に、まず組み込み機能とワークスペース設定を使いこなすと、環境差を減らせます。

## 日常の編集フロー

1. `Ctrl+Shift+V`でプレビューを開き、`Ctrl+K V`で横に並べます。
2. アウトラインで見出し階層を確認します。
3. `Ctrl+Shift+O`で現在のファイルの見出しへ移動します。
4. `Ctrl+T`でワークスペース内の見出しを検索します。
5. 編集後にリンク検証とLinterを実行します。

プレビューは編集内容に追従し、エディターとスクロールも同期できます。[1]
ただし、VS
Codeでの見え方だけで公開先の挙動を保証することはできません。GFM、Starlight、社内Wikiなど実際の公開先でも確認してください。

## リンクを壊さない設定

このリポジトリには`.vscode/settings.json`を用意しています。ローカルリンク検証を有効にし、ファイル移動時にリンク更新を提案する設定です。

```json
{
  "markdown.validate.enabled": true,
  "markdown.updateLinksOnFileMove.enabled": "prompt"
}
```

リンク検証はローカルのファイル、見出し、画像、参照リンクを確認します。外部HTTP(S)リンクは対象外なので、CIまたは定期点検で別途確認してください。[1]

見出しを変えるときは、単純な文字列置換を避けます。見出し上で`F2`の**Rename
Symbol**を使うと、同じワークスペース内の該当リンクを更新できます。[1]

## 画像を貼り付ける

ファイルや画像をエディターへドラッグ＆ドロップ、または貼り付けると、VS
CodeはMarkdownリンクとして挿入できます。ワークスペース設定の`markdown.copyFiles.destination`で、画像の保存先を文書種別ごとに決められます。[1]

このリポジトリでは、ドキュメントから貼り付ける画像の候補先を`public/images/${documentBaseName}/`にしています。画像を追加したら、次を確認してください。

- ファイル名が内容を表しているか。
- 代替テキストに読者が必要とする情報があるか。
- プレビューと公開サイトの両方でパスが正しいか。
- 画像内に秘密情報、個人情報、ライセンス上の問題がないか。

## AI支援を使う場合

VS
Codeでは、AIを使ってMarkdown画像の代替テキストを生成または改善できる機能も案内されています。[1]
ただし、自動生成された説明は誤認、過不足、機密情報の読み上げを含む可能性があります。画像の目的、読者の次の行動、本文との重複を人が確認してから採用してください。

AIに文書を下書きさせる場合も同様です。対象読者、公開先、禁止事項、根拠資料を明示し、出力後にリンク・事実・コード・手順を検証します。

## 推奨するレビュー観点

| 観点             | 確認する質問                                           |
| ---------------- | ------------------------------------------------------ |
| 構造             | 最初の見出しだけで文書の目的が分かるか。               |
| 導線             | 関連ページへのリンクが必要な場所にあるか。             |
| 表示             | 長い表、深すぎるリスト、折りたたみが読みにくくないか。 |
| 可用性           | コマンドとコード例を実行またはビルドで検証したか。     |
| アクセシビリティ | 画像の代替テキストとリンク文言が意味を持つか。         |
